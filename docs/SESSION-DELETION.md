# 社区会话删除适配（preview.59）

在「会话 → 已归档对话」中接入可选的 [dsh-session-manager](https://github.com/hkkz9522/dsh-session-manager) 0.6.3。PF 不捆绑或自动安装该插件，也不增加模型删除工具。请在原生插件管理中安装并启用该版本，然后点击「重新检查删除服务」。

原生「添加插件」填写 `dsh-session-manager@0.6.3`。该版本 npm 元数据的 gitHead 与本次核查提交一致。

当前开放范围：Windows、DSH Web 0.2.0-rc.2、原生 JSONL 存储。其他版本暂不开放，避免把未验证的删除行为当作兼容。

## 使用

1. 先归档会话。若仍被 DSH 占用，请在方便时重启 DSH，再进入归档列表；不要先打开该会话。
2. 点击「永久删除」，核对标题、会话 ID 和删除范围后确认。确认有效期为两分钟，过期或记录变化需重新确认。
3. 只有社区插件确认文件删除、PF 核对持久化记录及工作区/归档/置顶索引均不存在后，才显示成功。

永久删除涵盖会话存储目录及社区插件的独立会话标记，不能撤销。不清理工作区文件、长期记忆、导出日志或已有备份。社区标记清理失败会保留警告。

## 保护与限制

- 从已归档原始父会话发起，包含全部层级子代理；组内所有记录都不能有存活 Agent 或 Session。普通分叉及其关联会阻止删除，不默认连带清理。
- 删除期间持有宿主公开接口的独占写入句柄，不修改私有注册表、不强行停止模型。正在使用或尚未释放的写入者会阻止删除。
- 调用固定社区接口 `/session-manager/api/delete`；PF 不自行递归删除会话目录。目录与文件头校验由社区插件执行。
- 同一会话不能并发提交删除；确认令牌绑定全部成员及记录版本且只能使用一次；先锁定整组，再从最下层删除。
- 连接失败不自动重试；如果无法确认社区处理已结束，保护锁保留至宿主退出，需重启后核对。明确失败也可能发生部分清理，界面刷新并显示异常，不伪装成功。
- Windows 独占锁是内核信号量。其他平台删除锁文件时语义不同，本版不开放。
- 这些保护适用于 PF 入口；社区插件自己的界面和 API 仍由它独立管理。
