# 纸航命名与旧版迁移

产品名：**纸航 Paperflight**。对外完整名称：**纸航 Paperflight for DSH**。说明文字：**DSH 的非官方未来复古 Web 界面**。

UI 不加到品牌名或插件包名末尾：项目还包含本地服务、审批与可选工具，不只是皮肤。README、市场描述和设置页使用上述说明文字；前端私有构建包可用 UI 标明模块职责。

| 对象 | preview.48 起的名称或处理 |
| --- | --- |
| GitHub 仓库 / 插件包 | dsh-paperflight |
| 完整源码包 | dsh-paperflight-source |
| 私有前端构建包 | dsh-paperflight-ui（保留前端独立版本号） |
| 原生客户端模块 ID | dsh-paperflight，必须与插件包相符 |
| 插件实例 ID / 导出名 / 设置栏目 ID | 保留 mai-shell，便于沿用已有标识 |
| 数据目录 | 保留 DSH_HOME/mai-shell/<profile>，不移动或删除工作区 |
| HTTP 路由、启动票据、Cookie、环境变量、浏览器本地偏好键 | 保留既有协议与存储键，避免登录态和偏好失效 |
| 模型工具名 | 保留 mai_cmd、mai_browser，避免旧会话工具记录及工具策略失配，不注册重复别名 |
| 普通代码变量、CSS 类、历史变更记录 | 无需为改品牌批量重命名 |
| 上游版权、来源与许可证 | 保留真实作者及 MaiBot 名称，不冒充原创 |

## 已装旧包的电脑

包名变更不是常规的同名升级。preview.47 及以前的 dsh-mai-shell 与新包不可同时运行：它们使用相同服务、路由和默认端口。

1. 结束当前模型、终端与浏览器操作，记录旧插件自定义配置（尤其端口），按需备份纸航数据。
2. 在对应 DSH 配置的原生插件管理中**卸载 dsh-mai-shell**，不要只停用，也不要删除整个 DSH_HOME 或 mai-shell 数据目录。
3. 在同一 DSH 配置中安装 dsh-paperflight 的 preview.48 tgz，按宿主提示刷新或重启空闲服务；自定义实例配置可能需要重新填写。
4. 从原生设置「纸航 Paperflight」进入，确认旧会话、工作区文件、偏好及工具开关状态。旧用户的工具开关沿用旧设置，只有全新数据目录默认关闭。

共享浏览器的临时页面、登录态和运行中的命令不会跨卸载保存。不承诺无停机升级，不自动卸载其他包或删除用户数据。

回退时先在空闲状态卸载 dsh-paperflight，再安装保留的旧版 dsh-mai-shell 包；沿用相同配置和数据目录。不要同时装两版。命令中的 --profile 必须对应正在测试的配置。

## 验证边界

本地包检查必须核对 package.json、Cordis 包引用和客户端模块 ID 一致，并确认兼容标识没有被批量替换。静态检查和构建不等于真实宿主迁移验收；另一台 Windows 上需测试全新安装，有旧版的测试环境还需测试卸载旧包→安装新版→回退。
